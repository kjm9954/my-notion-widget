각 주소에 **원본과 다른 새 세트의 `?w=` 값**을 동일하게 붙입니다. 여섯 위젯은 새 키 하나를 공유합니다. 원본 기록을 한 번 복사한 뒤에는 원본과 자동 동기화하지 않습니다. 개인 키와 실제 기록은 공개 소스·문서·스크린샷·배포 ZIP에 넣지 않습니다.
새 화면은 `data-store-isolated`를 선언해 주소의 명시적인 `w`만 사용합니다. 예전 localStorage·업무 키 캐시·키 발견 채널에서 인스턴스를 가져오거나 그 값을 덮어쓰지 않습니다. 키가 없거나 잘못되면 API 요청을 차단합니다. 기존 화면의 연결 방식은 유지합니다.
WORK LOG의 **목표 칸은 클릭할 때마다 미선택 → 1 → 2 → 3 → 미선택**으로 바뀝니다. 선택한 업무는 이번 주 목표에 지정 번호와 함께 **1 → 2 → 3 순서**로 표시됩니다. 같은 번호의 업무도 모두 별도 행으로 표시하며 3개로 제한하거나 합치지 않습니다. 각 행은 해당 업무의 완료 여부를 `0 / 1` 또는 `1 / 1`로 표시합니다. 별도 목표 생성은 필요하지 않습니다. 선택 해제하면 자동 목표가 사라지고, 완료 체크는 목표의 완료 수만 갱신합니다. 업무 제목·날짜를 바꾸면 목표 문장·주차도 함께 반영됩니다.
번호는 기존 작업 API의 `goalId`에 `worklog:goal:1`~`worklog:goal:3`으로 저장하고 각 업무의 ID·제목·날짜에서 목표 행을 도출합니다. 새 저장 키·API·서버 배포나 `weeklyGoals` 중복 저장이 필요하지 않습니다. 이전 체크 방식(`goalId === id`)은 1번으로 읽고 다음 클릭부터 2번으로 이어지며 자동 데이터 변환은 하지 않습니다. 저장된 독립 주간 목표와 다른 목표를 참조하는 기존 업무 연결은 계속 읽습니다. 별도로 등록한 목표의 편집기는 `Worklog/weekly-goals.html?w=새키&isolated=1`이며 자동 표시되는 업무 목표의 편집은 WORK LOG에서 합니다.
WORK LOG에서 Q를 바꾸면 해당 날짜를 **Q1 → Q2 → Q3 → Q4 → 미지정** 순으로 재정렬하고 저장합니다. 업무 추가·날짜 이동도 반영합니다. 같은 Q 안에서는 기존 수동 순서를 유지하며 다른 날짜·모드는 변경하지 않습니다. 직접 드래그한 순서는 다음 Q 변경까지 유지되고 제목·완료·목표 번호 편집으로 초기화되지 않습니다. 목표 번호와 Q는 서로 독립입니다. 모바일은 기존처럼 미완료/완료 그룹을 유지하며 그룹 안에서 정렬합니다.
프로젝트는 개별 Notion 임베드 구조이므로 페이지 전체 배치는 Notion에서 조절합니다.
모바일 순서: 목표 → WORK LOG → 마감 → 메모 → 한 일 → 달력.
3일 안 마감은 화면 안 제목과 제목 자리의 여백 없이 목록부터 표시합니다. 브라우저 탭 제목·접근성 이름, 빈 상태·오류 안내, 세로 높이 조절과 데이터 연결은 유지합니다.

## 읽기 화면 디자인 v2

요청 패키지의 `widgets.css`/`widgets.js`에 대응하는 운영 파일은 `read-widgets.css`/`read-widgets.mjs`이며 순수 날짜·집계 함수는 `read-widgets-model.mjs`에 있습니다. 목표 스타일만 `weekly-goals.css`로 분리했고 목표의 번호 선택·집계·렌더링 로직은 변경하지 않았습니다. 저장·구독·날짜 기준·업무 필드·Store API도 그대로입니다.

- 마감: 개별 항목 카드와 같은 폭의 알약 배지. D-DAY 올리브, D-1 노랑, D-2/3 연올리브. 날짜순 → 같은 날짜 Q순 → 기존 순서로 최대 5건입니다. 420px 미만에서 업무명은 최대 두 줄이며 잘린 제목은 마우스에서만 툴팁으로 표시합니다.
- 한 일: 완료 → 미완료 그룹, 각 그룹 Q순. 두 그룹이 모두 있는 요일에만 구분선을 표시합니다. 오늘 제목 줄은 노란 띠와 오늘 태그입니다. 600px 이상에서는 flex 5열의 배경 높이가 같고, 그 미만에서는 요일별 자연 높이로 세로 배치됩니다.
- 달력: 월~일 7열의 떨어진 타일, 오늘 노란 면, 주말/다른 달 구분. 마감 점은 4개씩 줄바꿈합니다. 420px 미만에서는 6px 점과 작은 타일을 사용하고 오늘 태그만 숨깁니다.
- 목표: 새 카드·목록 색, 18px 카드 모서리, 제목/완료 수 굵기 변경. 긴 목표 문장과 410px 이하 완료 수 줄바꿈은 유지합니다.

기기 종류가 아니라 `@container wr-widget`의 실제 폭으로 600px/420px 반응형을 적용합니다. 목표의 기존 410px 구간은 유지합니다. 글자 축소를 막는 `data-widget-layout-resize`는 이 네 화면에만 적용합니다. 예전 scale 설정이 있어도 글자를 줄이지 않고 실제 레이아웃 폭을 맞추며, 모서리 손잡이도 글자 크기를 유지한 채 카드 크기만 바꿉니다. WORK LOG·메모와 기존 위젯은 이 옵션을 사용하지 않습니다.

## 공통 프리텐다드 웹폰트

여섯 크림·올리브 위젯은 모두 `../pretendard.css`와 자체 호스팅한 **Pretendard Variable v1.3.9 전체 WOFF2**를 사용합니다. 기기에 설치된 글꼴이나 외부 CDN을 사용하지 않고 같은 버전을 다운로드합니다. 메모의 미리보기용 `WLPreview` 서브셋은 제거했습니다. 본문·제목·버튼·입력창·툴팁·초기 로딩·연결 오류 안내에 같은 글꼴이 적용됩니다. 기존 글자 크기·굵기·데이터 동작은 유지합니다.

글꼴 원본은 [Pretendard 공식 배포본](https://github.com/orioncactus/pretendard/tree/v1.3.9)입니다. `assets/fonts/pretendard-1.3.9/`에 변경하지 않은 글꼴, OFL 라이선스와 출처·해시를 함께 보관합니다. 각 HTML에서 같은 URL을 preload하므로 브라우저가 페이지 간 캐시를 재사용할 수 있습니다. ZIP에도 이 파일과 공통 CSS를 포함해야 합니다.

최초 웹폰트 다운로드는 네트워크가 필요합니다. 다운로드 실패·브라우저의 웹폰트 차단 시에는 가독성을 위해 시스템 대체 글꼴을 사용합니다. OS별 안티앨리어싱이나 폰트가 지원하지 않는 문자까지 동일한 모양을 보장하지는 않습니다.

## 반복 조회 절감 및 하루 한도 처리 (2026-09-29)

새 여섯 화면만 `data-store-coalesce`를 선언합니다. 기존 위젯 HTML·화면·주기는 유지하며, 공통 Store의 저장 응답 공유와 한도 오류 인식은 함께 개선합니다. Worker, 데이터베이스, 요금제, 실제 기록은 변경하지 않습니다.

- 새 위젯의 자동 확인 주기: 2분. 업무/메모의 성공 응답은 2분, 독립 목표 응답은 5분 동안 재사용합니다. 독립 목표는 2분 감시 주기와 결합해 대기 중 약 6분 간격으로 다시 조회될 수 있습니다. 다른 기기나 별도 저장소 구획의 변경은 다음 확인 때 반영됩니다.
- 같은 브라우저 저장소 구획·같은 키·같은 API의 동시 조회는 Web Locks와 기존 Cache Storage로 합칩니다. 데이터는 기존 인스턴스별 URL에 보관하고 확인 시각만 로컬 응답 헤더에 추가합니다. 다른 키의 기록/캐시는 섞지 않습니다.
- 업무 응답이 오래되면 기존 `/api/worklog/revision`으로 변경 번호와 업무일을 확인합니다. 둘 다 같으면 전체 목록을 다시 읽지 않고 확인 시각만 갱신합니다. 변경되었거나 한국 오전 6시 업무일이 바뀌면 전체 업무를 읽습니다. 목표/메모는 한국 자정을 넘기면 캐시를 다시 확인합니다.
- 같은 브라우저에서 저장 성공 시 서버의 저장 응답을 공통 캐시에 먼저 반영하고 변경 알림을 전송합니다. 완료/목표 번호 변경은 다음 정기 조회를 기다리지 않고 화면에 반영됩니다. 저장과 조회가 겹치면 동일 URL 잠금으로 순서를 보장합니다. 변경 알림의 경로를 구분해 메모 변경이 업무·목표 재조회를 일으키지 않습니다.
- Web Locks 또는 캐시 사용이 불가능한 환경에서도 기존 API로 동작합니다. 이 경우 iframe 간 중복 억제 효과는 줄어들 수 있습니다. API 접근이 허용되지 않는 임베드에서는 잠금을 우회하되 실패한 저장 요청 자체를 재전송하지 않습니다. 공유 조회에는 본문 수신을 포함한 15초 타임아웃을 둡니다.
- `HTTP 500`의 실제 `D1_ERROR ... free tier daily row read/write limit`도 한도 초과로 인식합니다. 기존 Worker `1027`/`429` 처리도 유지합니다. 한도 정보는 같은 저장소 구획의 위젯과 새 문서에 공유하며 한국 오전 9시 초기화 직후부터 정기 확인을 재개합니다. 이미 진행 중인 요청의 성공이 대기를 취소하지 않습니다.
- 읽기 화면에서는 오류를 빈 상태로 바꾸지 않습니다. 실패 시 같은 키의 마지막 정상 응답을 복원하고 `이전 데이터 표시 중` 안내를 유지합니다. 서버의 한도 초과 대체 스냅샷도 이전 자료로는 사용할 수 있지만 최신 성공 응답으로 취급하지 않습니다. 이용 가능한 이전 업무 자료가 전혀 없을 때만 로딩 실패로 표시합니다. 이미 소진된 계정 한도는 이 수정으로 복구되지 않습니다.

기존 WORK LOG는 로컬 캐시와 서버의 업무 스냅샷 대체 경로를 사용합니다. 새 여섯 화면도 아래 후속 수정으로 이전 자료를 표시하되 오래된 상태임을 알립니다. 화면이 보이는 것만으로 현재 서버 저장이나 신규 조회가 정상이라는 뜻은 아닙니다.

### 한도 초과·연결 실패 시 이전 자료 표시

- 같은 키의 업무·목표·메모 캐시를 새로고침 후에도 복원합니다. 실패는 여전히 실패로 전달하고, 표시용 이전 데이터만 별도로 제공하므로 성공 시각을 갱신하거나 한도 대기를 해제하지 않습니다. 다른 키의 자료, 샘플, 저장 실패한 요청은 캐시에 넣지 않습니다. 401/403/404 같은 권한·키 오류에는 캐시를 대신 제공하지 않습니다.
- 네 읽기 화면은 `ready`(정상), `stale`(이전/일부 자료와 경고), `error`(표시할 자료 없음)를 구분합니다. 실제로 비어 있던 이전 자료도 빈 화면과 경고를 함께 복원합니다. 업무는 있지만 목표 캐시만 없으면 업무는 보여주고 목표 정보 미확인을 명시합니다. 목표가 없다는 정상 빈 상태로 단정하지 않습니다.
- WORK LOG와 메모에도 지속적인 이전 자료 안내를 표시합니다. 캐시 표시 중에는 업무 편집·완료 변경·메모 편집을 막고, 자동 업무 이월/메모 정리도 실행하지 않습니다. 서버 연결이 복구되면 정상 조회 후 안내와 읽기 전용 제한을 해제합니다. 기존 입력 중 내용은 동기화 방지 규칙으로 보호합니다.

## 크기 설정의 기기 간 공유

2026-09-30 후속 변경입니다. 애니메이션은 변경하지 않습니다. 여섯 HTML만 크기 공유에 참여하며, 기존 위젯의 크기 저장·동작은 유지합니다.

- 새 `/api/widget-layout`은 같은 인스턴스의 여섯 크기 설정을 GET 한 번으로 반환합니다. 브라우저 Cache Storage와 Web Locks로 조회를 합치고 10분 동안 재사용합니다. 크기 설정 전용 정기 조회 타이머는 없습니다. 새 문서 진입·포커스/화면 복귀·온라인 복귀 시 캐시가 10분 이상 지났을 때만 다시 읽습니다. 열어둔 다른 기기가 즉시 바뀌는 실시간 동기화는 아닙니다.
- 드래그 중에는 저장하지 않습니다. 손잡이를 놓거나 키보드 크기 조절이 멈춘 뒤 500ms 동안 모아 마지막 값만 POST합니다. 이미 확인한 같은 값은 다시 저장하지 않습니다. 성공 응답을 먼저 캐시에 병합하고 알림을 보내므로 같은 브라우저의 다른 임베드는 추가 GET 없이 반영합니다.
- 크기는 `instance:<key>:widgetLayout:v1:<widget>` 이름의 기존 `widget_settings` 행에 저장합니다. 등록 키 조회와 최대 여섯 설정 행의 인덱스 조회만 사용합니다. 작업 목록·메모·목표·이월·자동 정리 API를 호출하지 않고 DB 테이블을 만들거나 기존 기록을 초기화하지 않습니다. 위젯 하나를 저장할 때 다른 다섯 행은 건드리지 않습니다.
- 브라우저 크기 키도 `data-widget-key + ':' + instance`로 구분합니다. 기존 키는 표시 호환용으로만 읽습니다. 예전에 저장한 기기별 크기를 자동으로 서버에 올리지 않으므로, 배포 후 원하는 PC에서 각 손잡이를 한 번 조절해야 공유가 시작됩니다. 새 서버 설정이 있으면 이를 우선합니다. URL에 직접 넣은 높이/배율 등의 기존 우선순위는 유지합니다.
- iPad/모바일도 같은 설정을 불러오되 화면 폭·높이에 맞춰 표시하고 모바일의 기존 재배치를 유지합니다. 작은 화면에 맞춘 결과는 다시 저장하지 않습니다. 터치용 크기 조절 기능을 새로 추가한 것은 아닙니다.
- 저장 실패는 로컬 크기를 유지하고 `이 기기에만 저장` 안내를 남깁니다. 실패 저장을 자동 반복하거나 새로고침 후 옛 변경을 서버에 밀어 넣지 않습니다. 연결 복구 후 손잡이를 다시 조절하면 저장합니다. 조회 실패는 마지막 크기를 유지하면서 알리고 1분간 같은 조회 실패를 합칩니다. 기존 하루 한도 대기는 크기 요청에도 적용됩니다.
- 캐시/잠금을 차단하는 임베드나 서로 다른 저장소 구획에서는 중복 억제 효과가 줄어듭니다. 전부 새 기기라면 각 기기에서 첫 GET이 필요하며, POST의 CORS 사전 요청은 브라우저 정책에 따라 별도로 발생할 수 있습니다.

서버 모듈은 `widget-layout-api.mjs`의 `withWidgetLayouts(existingWorker)`입니다. 운영 서버에서 내려받은 정확한 원본을 감싸고, 크기 경로만 처리하며 나머지 API와 scheduled 핸들러를 유지합니다. **저장소의 오래된 `worker.js`를 대신 배포하지 마세요.** 운영 원본·설정은 비공개 작업 폴더에 보관하고 공개 ZIP에 넣지 않습니다. 기존 D1/KV 바인딩·비밀 값·환경 변수·cron은 유지하며 크기 endpoint 추가에만 사용자 승인을 사용합니다.

## 원본 복사 상태와 안전 조건

소스·정적 화면 준비와 사용자 기록 복사는 별도 단계입니다. 원본 임베드 주소/키가 확인되기 전에는 새 인스턴스를 만들거나 기록을 읽고 복사하지 않습니다. 실제 키·기록·개별 복사 결과는 공개 문서가 아닌 개인용 인계 문서에서 관리합니다.
복사 대상은 업무 상태(업무·일상 기록/정렬/표시 설정), 주간 목표, 메모입니다. 일기·독서·Q&A 및 다른 데이터는 복사하지 않습니다. 원본을 삭제하거나 새 키에 원본을 계속 연결하는 별칭을 만들지 않습니다.
주의: 기존 `/api/worklog/state` 조회도 서버 자동 이월로 원본 업무 날짜를 바꿀 수 있고, 메모 조회는 과거 완료 날짜를 보정할 수 있습니다. 원본 불변을 보장하려면 관리자 읽기 전용 스냅샷/내보내기 등 부작용 없는 원본 추출 경로를 먼저 확보해야 합니다. 확인 없이 일반 조회를 대량 실행하지 않습니다.
복사 전 원본 스냅샷을 비공개로 보존하고, 새 키가 원본과 다른지 및 대상이 비었는지 확인한 뒤 새 대상에만 기록합니다. 완료 확인은 항목 ID·내용·완료·목표 연결·정렬을 대조합니다. 중간 실패 시 성공했다고 표시하거나 원본에 쓰지 않습니다.
새 메모 v9를 열면 과거 날짜의 완료 메모는 **새 복사본에서만** 기존 기능대로 정리될 수 있습니다. 새 WORK LOG의 이월 역시 새 복사본에만 적용됩니다.

## 공개본과 제작본의 차이 / 남은 연결

## 적용 주의

공개 저장소 main은 기존 Pages 자동 배포 대상입니다. 승인 없이 main에 반영하거나 Worker를 재배포하지 않습니다.
ZIP은 위 변경 파일의 전체 내용과 실행에 필요한 기존 `widget-frame.css`, `schedule-core.js`를 담습니다. 기존 main 위에 적용하는 묶음이며 신규 독립 DB/서버를 구성하는 패키지가 아닙니다.
다른 로컬 변경이 있다면 덮어쓰기 전에 보존하고 차이를 확인합니다. 새 HTML은 ES 모듈이므로 HTTP(S)로 엽니다.
